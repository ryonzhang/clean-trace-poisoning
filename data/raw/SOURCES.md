# Trace Corpus Sources

This file documents the provenance of all raw trace corpora used in the cleantrace-data pipeline.

---

## 1. texada-bundled

**Description:**
Test traces from the ModelInference/texada GitHub repository, specifically from the `traces/` directory. These are the canonical example traces bundled with the Texada LTL property miner and serve as a ground-truth reference set. Each file contains one or more traces in Texada format (events one per line, blank line between traces).

**License:** MIT

**URL:** https://github.com/ModelInference/texada

**Files fetched:**
- `login.txt` — login/logout/fail trace sequences
- `example2.txt` — simple abstract event traces (a, b, c)
- `mult-trace.txt` — multi-trace file with abstract events

**Fetch method:** GitHub raw content API (`https://raw.githubusercontent.com/ModelInference/texada/master/traces/`)

**Note:** Fetched via GitHub raw API. If the file is unavailable at fetch time, a hardcoded fallback is used and noted in the log. The fallback content matches the known content of these files as of 2024.

## 2. crv2014

**Description:**
Benchmark traces from the Competition on Runtime Verification 2014 (CRV 2014). This competition evaluated runtime verification tools on a variety of trace benchmarks covering concurrent programs, Java library monitors, and protocol specifications.

**URL:** https://www.react.uni-saarland.de/tools/crv2014/

**License:** See competition website for individual benchmark licenses.

**Note:** If the CRV 2014 trace files are unavailable at fetch time (e.g., due to server downtime or the individual trace files not being directly parseable from the index page), this corpus is SKIPPED and a synthetic fallback is generated instead. The synthetic fallback uses CRV-like event names (`req`, `ack`, `data`, `fin`, `rst`, `syn`) to produce plausible protocol traces. This event is logged below as `CRV2014_STATUS` when it occurs.

**Synthetic fallback:** 200 traces, events drawn from `{req, ack, data, fin, rst, syn}`, lengths 5–18, seed controlled by `--seed` argument to `fetch.py`.

## 3. dacapo-synth

**Description:**
Synthetic execution traces generated by instrumenting a small Python program covering fibonacci computation and sorting routines. Traces are produced by a custom event logger that records function entry and exit events. Each trace represents one simulated execution path through the routines.

**Event vocabulary:** `{fibonacci.enter, fibonacci.exit, sort.enter, sort.exit, search.enter, search.exit, merge.enter, merge.exit, quicksort.enter, quicksort.exit, bsearch.enter, bsearch.exit, heapsort.enter, heapsort.exit}`

**License:** Generated; no restriction.

**Fully reproducible from script:** Yes. Running `scripts/fetch.py` with the same `--seed` value will always produce the same traces.

**Note:** 250 traces, lengths vary by nesting depth (3–12 top-level calls per trace, with optional inner calls).

## 4. fsm-generated

**Description:**
Traces generated from 3 hand-coded finite-state machines representing common software protocol patterns:

1. **Request/Response FSM** — models a client-server request lifecycle: `IDLE -> (REQ) -> PENDING -> (ACK) -> ACTIVE -> (RESP|END) -> IDLE`
2. **Lock/Unlock FSM** — models a mutex: `UNLOCKED -> (LOCK) -> LOCKED -> (UNLOCK) -> UNLOCKED`, with TRY_LOCK / TRY_UNLOCK no-ops
3. **Open/Read/Write/Close FSM** — models file I/O: `CLOSED -> (OPEN) -> OPEN_RD -> (READ|WRITE|SEEK|STAT)* -> (CLOSE) -> CLOSED`

Each trace is produced by one of the three FSMs, selected uniformly at random.

**License:** Generated; no restriction.

**Seed:** 42 (controlled by `--seed` argument to `fetch.py`).

**Total:** 300 traces.

## 5. posix-syscall

**Description:**
Trace log of POSIX-like system call sequences. Traces are generated by simulating common system call patterns drawn from Python's `os` module and standard POSIX APIs. Four sequence generators are used:

1. **File I/O** — `open, (read|write|lseek|fstat)*, close`
2. **Process** — `fork/exec/wait/exit` or random `getpid/getppid/signal` sequences
3. **Network** — server (`socket, bind, listen, accept, (send|recv)*, shutdown`) or client (`socket, connect, (send|recv)*, shutdown`)
4. **Memory** — `mmap, (mprotect|mlock)*, munmap`

**License:** Generated; no restriction.

**Seed:** 42 (controlled by `--seed` argument to `fetch.py`).

**Total:** 250 traces.

## Synthetic Fallback Policy

For any corpus that cannot be fetched from its upstream URL at pipeline run time, the fetch script will:
1. Print a `[SKIP]` warning to stdout.
2. Append a `CRV2014_STATUS` (or equivalent) note to this file.
3. Generate a synthetic fallback with clearly labeled provenance.
4. Include the fallback in the SHA256 checksum registry (`data/raw/sha256sums.txt`).

The fallback ensures the downstream normalize, validate, and mine steps can run without external network access.

## 6. real-syscall

**Description:**
REAL system-call traces captured with `strace` from live Linux program executions. Each
traced process becomes one trace of file-descriptor lifecycle events
(open/read/write/lseek/stat/close/dup/mmap). Nothing is synthesized — every event is an
actual syscall issued by the program. Three behavioral classes are included:
well-behaved coreutils (cat, head, tail, wc, grep, cut, sha256sum, nl, rev, uniq),
Python file-I/O, and a small native program that `open()`s descriptors and `_exit()`s
WITHOUT `close()` — a real, legal behavior that relies on the OS to reclaim descriptors,
yielding genuine `open`-without-`close` counterexamples to the resource-safety property
`G(open -> F(close))`.

**License:** Generated from real execution; no restriction.

**Reproducible:** Yes — `python3 scripts/gen_real_syscall.py --seed 7 --leak-frac 0.0 --n-native-leak 8`.

**Note:** Per-trace source program (cat/grep/python/leak/...) is a NATIVE provenance signal
available for the provenance-quorum defense; see scripts/gen_real_syscall.py.

## 7. real-network

**Description:** REAL network/socket traces captured with `strace` from distinct real
client programs (`curl`, `wget`, `nc`, `ssh`, a Python client, a Python client that
shuts down before closing, and a native C client) connecting to a local loopback
HTTP/echo server. Each client process is one trace over the socket-lifecycle alphabet
{socket,bind,listen,accept,connect,send,recv,shutdown,sockopt,close}. A native C leak
client `connect()`s and `_exit()`s WITHOUT `close()`, giving genuine connect-without-close
counterexamples to `G(connect -> F(close))`.

**License:** Generated from real execution; no restriction.
**Reproducible:** `python3 scripts/gen_real_network.py --seed 7 --reps 8 --n-native-leak 5` (Linux; needs strace, gcc, curl, wget, nc, ssh).
**Native provenance:** `source_id` = client program.
